## Reflection

### 1. What went well during this unit?

Our team made good progress connecting backend functionality to the frontend and making StudySync more usable. We implemented study plan creation and listing, added realistic demo data, and improved the user experience by making newly created study plans appear immediately without refreshing the page. We also expanded automated tests, completed manual testing of the study plan workflow, and improved the README with setup instructions. Team members reviewed pull requests and helped identify issues before merging changes into the main branch.

### 2. What were some challenges your group faced in this unit?

One challenge was coordinating changes across different branches while multiple team members worked on related features. We also encountered issues with database setup and making sure new features worked with the existing schema without affecting shared data. During testing, we discovered that newly created study plans were saved successfully but did not immediately appear in the UI. We addressed this through a separate pull request and regression tests. Managing feature dependencies and keeping our documentation updated were additional challenges.

### 3. Did you finish all of your tasks in your sprint plan for this week? If you did not finish all of the planned tasks, how would you prioritize the remaining tasks on your list?

We completed several important tasks, including study plan creation and listing, UI updates, automated testing, and documentation improvements. However, not every planned task was finished. We would prioritize completing and verifying the remaining Milestone 4 issues, followed by resolving bugs that affect core functionality. After that, we would focus on features such as comments and other enhancements. We would also continue reviewing pull requests and testing completed functionality before moving on to additional features.

### 4. Which features and user stories would you consider “at risk”? How will you change your plan if those items remain “at risk”?

The Comments feature is currently at risk because its database schema, API, role permissions, and UI components still require implementation and coordination. Features that depend on unfinished backend functionality may also be delayed. To reduce these risks, we plan to clarify requirements earlier, assign clear ownership to individual subtasks, and prioritize foundational backend work before frontend integration. If time becomes limited, we will focus on completing and testing the core user stories before adding optional functionality.

### 5. What additional support will you need in upcoming units as you continue to work on your final project?

We would benefit from continued feedback on feature requirements, database design, and implementation priorities. More guidance on integrating frontend and backend functionality, handling user roles, and testing complete workflows would also be helpful. As we approach the final submission, we want to make sure our remaining features meet the project requirements and that our documentation and demonstrations accurately reflect the completed work.
